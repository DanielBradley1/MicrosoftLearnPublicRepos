# Baseline security mode settings

As a Microsoft 365 admin, you can use Baseline security mode settings to protect and secure your business environment against external threats.

Baseline security mode helps you:

- Protect business data.
- Prevent business disruption.
- Block unsafe end user practices.
- Secure internal accounts.
- Ensure secure collaboration.

Baseline Security Mode covers key Microsoft 365 services, including:

- Microsoft 365 apps.
- SharePoint and OneDrive.
- Microsoft Teams.
- Exchange Online.
- Microsoft Entra identity platform.

By using Baseline Security Mode in the Microsoft 365 admin center, you can set certain security settings that were previously available only in PowerShell.

Now that these settings are available in the admin center, your organization can carefully evaluate each of the Baseline Security Mode settings before deployment.

This article provides information about the Baseline security mode settings that you can turn on. It also has links to content that helps you understand what each setting does and why you should turn on the setting.

## Before you begin

Workload-specific administrators can manage only their own settings. To manage the settings you want to configure, make sure to sign in with an account that has the appropriate role. For example, to manage settings related to Microsoft Entra ID, sign in with an account that has the Security administrator role.

Baseline security mode settings support role-based access control \(RBAC\), so the following roles can also see these settings:

- [Office Apps administrator role](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference).
- [SharePoint administrator role](https://learn.microsoft.com/en-us/sharepoint/sharepoint-admin-role).
- [Exchange Administrator role](https://learn.microsoft.com/en-us/microsoft-365/admin/add-users/about-exchange-online-admin-role?view=o365-worldwide).
- [Teams administrator role](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference).

For more information, see [Microsoft Entra built-in roles](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference).

Important

You can configure Baseline security mode settings on all Microsoft 365 subscriptions and plans.

## Baseline security mode settings recommendation

Baseline security mode settings provide flexibility and control, so you can manage each setting independently. You can also experiment by disabling a setting for a defined period \(such as a few days\) to assess dependencies.

Run the Baseline security mode settings in this way:

- Run impact reports for each of the Baseline security mode settings.
- If the setting displays zero impacts, turn on that setting.
- If critical dependencies exist, don't turn on the setting. Plan to address those dependencies before making the changes permanent. This intuitive, phased approach ensures a smooth transition to secure-by-default configurations.

## How to access Baseline Security Mode settings

To access **Baseline Security Mode** settings, follow these steps:

1. Sign in to [Microsoft 365 admin center](https://go.microsoft.com/fwlink/p/?linkid=2024339).
2. From the left navigation bar, select **... Show all**, and then select **Settings** to expand it.
3. Under **Settings**, select [**Org Settings**](https://go.microsoft.com/fwlink/p/?linkid=2053743).
4. In the **Org Settings** page, select the [**Security and Privacy**](https://go.microsoft.com/fwlink/p/?linkid=2072756) tab.
5. In the **Security and Privacy** tab, select **Baseline Security Mode**.

## Authentication

This section outlines the options available to block insecure authentication methods in the Microsoft 365 admin center.

Important

Customers who accessed Baseline Security Mode in Microsoft 365 between November 2025 and early February 2026 might see two draft Microsoft Entra ID Conditional Access policies created in their tenant in a **Disabled** state. These policies are associated with Baseline Security Mode and might appear as created by the administrator who signed in to the Microsoft Baseline Security Mode page.

This behavior doesn't represent a security incident and has no effect on tenant security. The policies are in a disabled draft state. A fix is in progress to ensure policies are created only through explicit administrator action. Microsoft removes any unintentionally created policy drafts and notifies customers in advance.

### Exchange Web Services requirements

Before you disable EWS, make sure that you have the required build to avoid disruption of Outlook features and Office Add-ins. The following minimum build numbers are required:

- Microsoft 365: 16.0.20430.20092, which shipped in September 2026. This is for CC \(Current Channel\), MEC \(Monthly Enterprise Channel\), or SAC \(Semi-Annual Channel\).
- Office 2024 LTSC: 16.0.17932.20976, which shipped in September 2026.
- Teams panels: To avoid disruption, update your devices Teams app version 1449/1.0.97.2025120101, which was shipped in September 2025.

Note

These statements and build requirements are for Win32 Microsoft 365 Apps \(Office\) build only.

#### Impact of baseline security mode settings on Authentication

Currently, the following feature doesn't work when you enable baseline security mode settings:

- Certificate Based Authentication for Exchange ActiveSync \(legacy Exchange flow, not Microsoft Entra CBA flow\).

#### Impact of baseline security mode settings on the Exchange connector across Power Query supported hosts

Currently, the following features don't work when you enable baseline security mode settings:

- Excel for Windows.
- Excel for the web.
- Power BI and Microsoft Fabric - Power BI Desktop, Dataflows \(Gen1 and Gen2\), Power BI Web Modeling, Power BI Report Server.
- Microsoft Power Platform - Power Platform Dataflows \(Standard and Analytical\), Dynamics 365 Customer Insights.

#### Impact of baseline security mode settings on cross-tenant features

Currently, the following features don't work when you enable baseline security mode settings:

- Calendar sharing and Free/Busy \(cross-tenant/cloud\).
- MailTips \(cross-tenant/cloud\).

#### Impact of baseline security mode on hybrid deployments

- Turn off EWS access only after your hybrid Microsoft Exchange setup supports REST APIs. This change helps reduce legacy app usage and lowers the risk of data exposure.
- Server-side sync between Dynamics on-premises and Exchange Online doesn't work with this setting. To keep using sync features, [Connect Exchange Online to Dynamics 365 Customer Engagement \(on-premises\)](https://learn.microsoft.com/en-us/dynamics365/customerengagement/on-premises/admin/connect-dynamics-365-on-premises-exchange-online).

This section outlines the options available within OneDrive and SharePoint to turn off Baseline security mode settings in the Microsoft 365 admin center.

You must be a member of the [SharePoint administrator role](https://learn.microsoft.com/en-us/sharepoint/sharepoint-admin-role) to perform these tasks.

| Setting | More information |
| --- | --- |
| **Open ancient legacy formats in Protected View and disallow editing** | Ancient legacy file formats in Microsoft 365 apps \(formerly Office\) are vulnerable to memory corruption. When users open these outdated formats in Protected View with editing disabled, you prevent potential exploits while still allowing users to view the content without risk.  <br>  <br>For more information, see [Open ancient legacy formats in Protected View and disallow editing](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/open-ancient-legacy-formats-protected-view-disallow-editing?view=o365-worldwide). |
| **Open old legacy formats in Protected View and allow editing** | Many legacy file formats in Microsoft 365 apps \(such as older Word, Excel, and PowerPoint files\) are prone to memory corruption vulnerabilities. By opening legacy formats in Protected View, you minimize the risk of malicious code execution, while still allowing users to edit their content safely.  <br>  <br>For more information, see [Open old legacy formats in Protected View and allow editing](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/open-old-legacy-formats-protected-view-disallow-editing?view=o365-worldwide). |
| **Block ActiveX controls** | ActiveX controls are small programs used to add interactive features to Microsoft 365 documents and web pages. They're highly vulnerable to exploitation. Malicious actors often use ActiveX to run harmful code, install malware, or take control of a system, especially when users open compromised files or visit unsafe websites. Because of their history of security problems and declining usage, Microsoft 365 apps block ActiveX by default. Enforcing this setting ensures users in your environment can't override the default configuration.  <br>  <br>For more information, see [Block ActiveX controls in Microsoft 365 apps documents](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/block-active-x-controls?view=o365-worldwide). |
| **Block OLE graph and OrgChart objects** | Block OLE Graph and OrgChart objects. When you turn on this setting, Microsoft 365 apps block loading OLE Graph and OrgChart objects to protect users from known exploitation techniques.  <br>  <br>For more information, see [Block OLE Graph and OrgChart objects](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/block-ole-graph-org-chart-objects?view=o365-worldwide). |
| **Dynamic Data Exchange \(DDE\) server launches are blocked in Excel** | Windows Dynamic Data Exchange \(DDE\) allows Excel to pull data from external sources in real time. However, if the source is malicious, it can send harmful code to Excel and potentially compromise the system without requiring macros or other active content. Attackers use this technique in targeted phishing attacks to execute arbitrary commands. Blocking DDE server launch reduces this risk. When you enable this setting, Excel blocks DDE server launches, helping prevent malicious external sources from injecting harmful code into spreadsheets.  <br>  <br>For more information, see [Block Dynamic Data Exchange \(DDE\) server launches in Excel](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/block-dynamic-data-exchange-server-launches-excel?view=o365-worldwide). |
| **Block Microsoft Publisher** | Publisher has a large attack surface and won't be included in Microsoft 365 starting in October 2026. Blocking Publisher now reduces security risk and aligns with Microsoft's support strategy. When you enable this setting, Microsoft Publisher doesn't launch.  <br>  <br>For more information, see [Block Microsoft Publisher](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/block-microsoft-publisher?view=o365-worldwide). |

## Room devices

This section outlines the options available within Teams to turn off Baseline security mode settings in the Microsoft 365 admin center.

You must be a member of the [Teams administrator role](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference) to perform these tasks.

| Setting | More information |
| --- | --- |
| **Don't allow resource accounts on Teams Rooms devices from accessing Microsoft 365 files** | To increase security, remove resource accounts access that Teams Rooms and devices use to access Microsoft 365 assets for meeting and collaboration.  <br>  <br>For more information, see [Set-SPOTenant](https://learn.microsoft.com/en-us/powershell/module/microsoft.online.sharepoint.powershell/set-spotenant) and the [restrict resource account access parameter](https://learn.microsoft.com/en-us/powershell/module/microsoft.online.sharepoint.powershell/set-spotenant#-restrictresourceaccountaccess). |
| **Only allow endpoint managed, compliant devices to sign in** | To increase security, only compliant, organization-managed Teams Rooms devices can sign in to Microsoft 365 applications and resource accounts can't be misused to authenticate from unmanaged devices.  <br>  <br>For more information, see [Block Teams resource account sign in to Microsoft 365 clients](https://learn.microsoft.com/en-us/MicrosoftTeams/rooms/block-non-compliant-teams-rooms-devices). |
| **Block unmanaged devices and resource account sign-ins to Microsoft 365 apps** | To increase security, block resource accounts used for Teams devices from being used to sign in to Microsoft 365 clients.  <br>  <br>For more information, see [Block Teams resource account sign in to Microsoft 365 clients](https://learn.microsoft.com/en-us/MicrosoftTeams/rooms/block-non-compliant-teams-rooms-devices). |
| **Require multifactor authentication for device enrollment** | Requiring multifactor authentication \(MFA\) for device enrollment ensures that only verified users can add new devices to your organization through Intune. Device enrollment based solely on passwords leaves organizations vulnerable, as attackers who obtain stolen or phished credentials can silently onboard rogue devices that gain access to corporate data and services. Enforcing MFA adds a strong identity check during enrollment, reducing the risk of unauthorized device additions, limiting attacker persistence, and strengthening your overall access security posture.  <br>  <br>For more information, see [Require MFA for device enrollment](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/require-mfa-device-enrollment?view=o365-worldwide). |
| **Require a device compliance policy** | Requiring a device compliance policy ensures that every enrolled device meets your organization’s minimum security standards before accessing corporate apps or data. Without this requirement, devices with no compliance policy are treated as compliant by default, which means unmanaged, outdated, or misconfigured devices can still connect to sensitive resources. Enforcing this setting marks such devices as noncompliant and blocks them until a valid compliance policy is applied. This setting helps prevent data exposure, reduces unauthorized access risk, and ensures device level security controls \(such as encryption, OS version checks, or threat protection baselines\) are consistently enforced across your environment.  <br>  <br>For more information, see [Require a device compliance policy](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/require-device-compliance-policy?view=o365-worldwide). |
| **Restrict the number of devices a user can enroll in Intune** | Limiting the number of devices a user can enroll helps reduce the risk of attackers exploiting compromised credentials to register large numbers of rogue devices in your organization. A high enrollment limit increases exposure because one breached account can be used to onboard many unauthorized devices without detection. Enforcing a lower enrollment cap minimizes the blast radius of leaked credentials, prevents mass enrollment attacks, and strengthens overall device governance by ensuring that users can only enroll a controlled number of trusted devices.  <br>  <br>For more information, see [Restrict the number of devices a user can enroll in Intune](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/restrict-total-devices-enrolled-intune?view=o365-worldwide). |
| **Alert users when a new device is enrolled** | Unauthorized device enrollments can provide attackers with persistent access, particularly when compromised credentials are used to register rogue devices. Enabling this setting notifies users when a new device is enrolled with their account, helping them quickly identify and report suspicious activity. Additional notification channels strengthen tenant security by reducing the risk of undetected access, data theft, and attacker-controlled devices.  <br>  <br>For more information, see [Restrict the number of devices a user can enroll in Intune](https://learn.microsoft.com/en-us/microsoft-365/baseline-security-mode/alert-users-new-device-enrolled?view=o365-worldwide). |
