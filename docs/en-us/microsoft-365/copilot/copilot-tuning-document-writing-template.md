# Copilot Tuning Document Writing agent template \(early access preview\)

The **Document Writing** agent template helps you generate long-form documents that align with your organization's style, structure, and workflows. By combining reference examples, content inputs, and optional tuning, the agent can draft documents that reflect how your team writes and works.

The template supports scenarios such as technical documentation, legal documents, reports, and other structured content.

Important

Microsoft Copilot Tuning is currently available to a limited set of customers through early access programs. Access through [Frontier](https://adoption.microsoft.com/copilot/frontier-program/) is planned for April 2026. Features and requirements are subject to change.

## What the Document Writing agent template can do

The Document Writing agent template enables you to:

- Create well-structured, long-form documents using reference examples and predefined templates.
- Customize format, tone, and writing style to meet organizational or customer standards.
- Generate drafts based on a sample reference file or template and deliver the output to your inbox.
- Configure and tune the agent to create a specialized Document Writing experience.
- Optionally perform deep tuning using your organization's data to further improve output quality.

## Try inferencing before tuning

Before you begin tuning, you can test the agent by running inference using either the default template or a test agent.

To start testing, use prompts that explicitly specify:

- One or more **reference files**
- One or more **content files**

Note

Due to a known limitation, prompts must currently use the exact phrasing: **Reference file is X and Instructions file is Y.** Support for additional variations \(such as *reference* and *instruction*\) is planned.

### Example inference prompt

> Draft new documentation using *Build\_Documentation.docx* as the reference file, and use the feature list from *DocGenAgentPRD.docx* as the instructions file.

The completed draft is delivered to your inbox after processing.

Note

Follow-up prompts are not currently supported by tuned agents. Follow-up suggestions shown in the experience are generated by the main Copilot and are not honored by the agent.

## Supported prompt patterns

### Example-based drafting

- Draft a partnership agreement using *Agreement 2024.docx* as a reference and the updated terms in *Term sheet Client A and Client B partnership.docx*.
- Create a vendor contract using *Contract 2024.docx* as a reference and the new clauses in *Notes Vendor ABC.docx*.

### Template-based drafting

- Draft a quarterly performance report using *Quarterly\_Report\_Template.docx* as the template and metrics in *Metrics\_Q1\_2025.xlsx*.
- Create a project status report using *Project\_Status\_Template.docx* as the template and the details in *Project\_Details\_March2025.docx*.

### Multiple-file drafting

- Draft a client engagement report using *Engagement\_Report\_Template.docx* and content from *Client\_Call\_Notes\_Jan2025.docx* and *Kickoff\_Notes\_Jan2025.docx*.
- Prepare a vendor agreement using *Vendor\_Conditions\_2025.docx* and *Master\_Contract\_2023.docx* as references, with content from *Supplier\_Agreement\_2024.docx*.
- Draft a partnership contract using *Partnership\_Obligations\_2025.docx* and formatting guidance from *Master\_Contract\_2023.docx* and *Supplier\_Agreement\_2024.docx*.

## Definitions and prerequisites

### Input files for the Document Writing agent template

The agent requires **two types of input files**, each serving a distinct purpose.

- **Reference file**: Defines *how* the document should look.
- **Content file**: Defines *what* information should be included.

Together, these files ensure the output is both **well structured** and **accurate**.

### Reference file

The reference file provides an example of the desired style, structure, and formatting. Think of it as the model the agent should follow.

Typical reference files include:

- Previously approved documents
- Standard team templates
- Precedent or example documents
- Ideal examples of the target document type

### Content file

The content file supplies the facts, instructions, and source material used to generate the document. This file focuses on content rather than structure.

Common content file examples include:

- Instructions or key points
- Meeting transcripts or notes
- Kickoff discussions
- Term sheets
- Technical specifications
- Source text or data to summarize or insert

## Seed data for evaluation

Prepare a small set of reference and content file pairs that represent your intended use case. These examples are used to simulate real-world usage and evaluate output quality during tuning.

## Tool tuning

If you plan to use tools as part of the agent recipe, create a private or shared **Style Editor \(Tone Alignment\)** agent and a **Document Reviewer** agent before starting tool tuning.

You can skip tool tuning and proceed directly to model tuning if needed. Tool tuning can be added later, at which point you can rerun evaluations.

## Model tuning data

To tune the model, prepare a folder containing **at least 20 example output files, each at least one page long,** that represent ideal results.

- Individual file selection isn't supported.
- You must select a folder.
- Supported file types include: `.txt`, `.pdf`, `.docx`, `.md`, `.html`, `.htm`, `.csv`.

Using larger datasets \(hundreds or thousands of files\) typically results in higher-quality improvements compared to out-of-box agents.

## Context tuning

### Define the goal and task

During context tuning, you define the agent's objective and expected behavior. Update the default goal prompt to reflect your scenario.

Consider including:

1. The user's role and document creation task.
2. The organization or company context.
3. Writing guidelines or quality constraints.
4. Instructions on how reference and content files should be used.

The following is an example of a goal definition:

- You are an expert technical writer responsible for drafting documentation aligned with Microsoft's tone and style.
- Follow the structure and formatting of the reference file.
- Insert or modify sections based on the content file instructions.
- Ensure technical accuracy and avoid introducing changes to intended product usage.
- Emphasize clarity, logical organization, accuracy, consistency, accessibility, and actionable guidance.

### Business category or industry

Specify one or more categories \(for example, Legal, HR, Project Management\) to further guide evaluation and tuning.

### File upload section

Upload example reference and content files that reflect typical user inputs. These files are used to simulate evaluation scenarios.

You must upload at least one and up to a maximum of 20 of each of the following file types:

- A **reference file** that defines *how* the document should look
- A **content file** that defines *what* the document should include

## Tune tools

If you select tools for the agent, choose the tuned versions available in your tenant and save your configuration. This triggers an evaluation run.

You receive an email when an evaluation completes. You can publish the agent immediately or continue tuning to improve results.

[![Screenshot of the tool tuning configuration interface showing available tuned tools.](https://learn.microsoft.com/en-us/microsoft-365/copilot/media/copilot-tuning-document-writing-template/tool-tuning-configuration.png)](https://learn.microsoft.com/en-us/microsoft-365/copilot/media/copilot-tuning-document-writing-template/tool-tuning-configuration.png#lightbox)

## Tune model

Model tuning lets you select training data, configure access, and start fine-tuning.

1. **Provide preferred outputs**  
   Select a folder containing at least 20 ideal output examples, each at least one page long.
2. **Review access**  
   Choose one or more Microsoft Entra security groups or restrict access to yourself.
3. **Start fine-tuning**  
   Select **Start fine-tuning** in the interface. Automatic startup isn't currently supported.
4. **Deployment**  
   After tuning completes, you receive an email to review results and publish the model.

[![Screenshot of the model tuning interface showing training data selection and fine-tuning options.](https://learn.microsoft.com/en-us/microsoft-365/copilot/media/copilot-tuning-document-writing-template/model-tuning-interface.png)](https://learn.microsoft.com/en-us/microsoft-365/copilot/media/copilot-tuning-document-writing-template/model-tuning-interface.png#lightbox)

## Use your tuned agent

You can use the agent after completing any stage: context tuning, tool tuning, or model tuning.

Inference prompts must still explicitly specify reference and content files.

Note

Follow-up prompts are not currently supported by tuned agents. Please ignore follow-up suggestions while this capability is under development.

The agent supports example-based, template-based, and multiple-file drafting patterns.
