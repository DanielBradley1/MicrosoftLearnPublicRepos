# Examine Azure AD Graph APIs app usage

> This article is step 2 in the [Azure AD Graph app migration planning checklist](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-planning-checklist) series.

While planning your migration to Microsoft Graph, take time to review your existing application and to catalog the Azure Active Directory \(Azure AD\) Graph APIs you're currently using.

Compare your list to the known differences. This helps identify specific changes you need to make to migrate your app. The nature of changes can range from simple changes easily resolved using an editor's search-and-replace features to more complicated updates that might require more analysis.

Microsoft Graph supports many of the same features and capabilities of Azure AD Graph, with a few key differences in the following categories:

- [Request differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-request-differences)
- [Feature differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-feature-differences)
- [Resource type differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-resource-differences)
- [Property differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-property-differences)
- [Method differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-method-differences)
- [Permissions differences](https://learn.microsoft.com/en-us/graph/migrate-azure-ad-graph-permissions-differences)
